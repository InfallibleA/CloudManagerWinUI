# CloudManagerWinUIApp

WinUI 3 приложение на .NET 10 (`net10.0-windows10.0.26100.0`).

---

## Где найти готовый .exe

### Портативная сборка (для распространения)

```
publish\portable\CloudManagerWinUIApp.exe
```

**Это один файл.** Ничего доустанавливать не нужно: ни .NET, ни Windows App SDK —
всё внутри. Можно просто скопировать на другую машину и запустить.

### Как его получить

Папка `publish/` добавлена в `.gitignore`, поэтому готовый `.exe` **не хранится в репозитории** — его нужно собрать.

**Через VS Code:** `Ctrl+Shift+P` → **Tasks: Run Task** → **`publish (portable .exe, один файл)`**

**Через терминал** (из корня репозитория):

```powershell
dotnet publish ".\CloudManagerWinUIApp.csproj" -c Release -p:Platform=x64 `
  -p:RuntimeIdentifier=win-x64 -p:WindowsPackageType=None -p:PublishSingleFile=true `
  -p:SelfContained=true -p:WindowsAppSDKSelfContained=true `
  -p:IncludeAllContentForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false `
  -o ".\publish\portable"
```

  > Тримминг в проекте отключён (`PublishTrimmed=false`). Release-сборка с триммингом
  > падает с `NullReferenceException` при добавлении элементов в WinUI-коллекции:
  > CsWinRT ищет ABI-хелперы (например, для `INotifyPropertyChanged`) рефлексией,
  > а триммер удаляет нужные поля.

## Настройка адреса сервера

Адрес API **не вводится в приложении** — он берётся из конфигурации и применяется при запуске.
Порядок поиска (первое найденное значение побеждает):

1. переменная среды `CLOUDMANAGER_API_URL`;
2. файл `appsettings.json` рядом с `.exe`;
3. значение по умолчанию — `http://localhost`.

Файл `appsettings.json` лежит рядом с собранным приложением (и попадает в сборку автоматически):

```json
{
  "Api": {
    "BaseUrl": "http://192.168.1.10:8080"
  }
}
```

* для **портативного `.exe`** — `appsettings.json` кладётся в папку рядом с `CloudManagerWinUIApp.exe`
  автоматически при публикации, его можно править на месте;
* ошибка в файле не ломает приложение: оно запустится на адресе по умолчанию, а причина
  будет показана на странице «Настройки» → «Подключение»;
* текущий адрес и источник значения тоже видны на странице «Настройки».

Изменения подхватываются после перезапуска приложения.

## Язык интерфейса

Приложение локализовано на **русский** и **английский**.

* при первом запуске язык выбирается автоматически по языку системы:
  язык интерфейса Windows → список языковых предпочтений → английский по умолчанию;
* если системный язык не поддерживается (не `ru` и не `en`), интерфейс будет английским;
* язык можно сменить в любой момент: **Настройки → Язык интерфейса** — интерфейс
  перестраивается сразу, без перезапуска;
* выбранный язык сохраняется в `%LOCALAPPDATA%\CloudManagerWinUIApp\user.json`
  и используется при следующих запусках.

## Админ-панель

Пункт меню **«Админ-панель»** виден только пользователю, вошедшему с ролью `admin`
(`UserResponse.Role == "admin"`). У остальных он скрыт, а сама страница, если её всё же
открыть, показывает «Нужны права администратора». При выходе или потере роли пункт меню
исчезает, а открытая админ-панель закрывается — приложение при этом не падает.

Внутри три вкладки: **«Пользователи»**, **«Файлы»**, **«Новости»**.

### Пользователи

* Таблица всех пользователей (`GET /api/auth/users`) с поиском по логину,
  фильтром роли (`Все` / `admin` / `client`) и кнопкой «Показать ещё»; счётчик показывает
  «Показано X из N».
* Колонка **«Статус»** показывает поле `is_blocked`: «Активен» или «Заблокирован»
  (у заблокированного дополнительно значок замка).
* Кнопка с замком в строке блокирует и разблокирует пользователя:
  `POST /api/auth/users/{id}/block` и `POST /api/auth/users/{id}/unblock`. Перед
  блокировкой показывается подтверждение, разблокировка выполняется сразу. Строка
  обновляется ответом сервера, поэтому список не перезагружается; повторная блокировка
  идемпотентна (`200`). Себя заблокировать нельзя — выводится сообщение, запрос не уходит.
* Клик по строке открывает проводник выбранного пользователя:
  «хлебные крошки» пути и таблица содержимого (значок — имя — размер — дата создания).
  Папки открываются кликом, возврат — по крошкам или кнопкой «К списку пользователей».
  Проводник стартует с корневой папки, которую отдаёт админский фильтр
  `GET /api/folders?root_only=true&creator_id=<id>`, а содержимое вложенных папок
  запрашивает через `GET /api/folders/{id}`. Доступ к чужой папке зависит от сервера:
  если он ответит `403`/`404`, страница покажет сообщение об ошибке, а список и
  «хлебные крошки» останутся на прежней папке.
  Дата создания в содержимом папки приходит не для всех записей, поэтому вместо неё
  (и вместо размера папки) показывается прочерк.

### Файлы

* Таблица **всех** файлов (`GET /api/files`): значок — имя — пользователь — тип — размер —
  дата создания. Владелец берётся из `creator_login`; если он `null` (служебные записи),
  показывается `creator_id`, а если нет и его — прочерк. Значок и цвет — те же, что у
  обычного файлового менеджера (`ExplorerIcons`), размер считается той же функцией,
  дата берётся из `created_at` и показывается в локальном времени.
* Фильтры уходят в query напрямую:
  * «Пользователь» → `creator_id` (выбранный аккаунт из `GET /api/auth/users`);
  * «Тип файла» → `type` (значения из `GET /api/files/types`, показываются как есть);
  * поле поиска → `name` (подстрока в имени файла, применяется по `Enter`).
* «Обновить» перезапрашивает первую страницу с текущими фильтрами, «Показать ещё» —
  следующую; счётчик «Показано X из N» строится по `count` из ответа. Ответы устаревших
  запросов отбрасываются, поэтому быстрые переключения фильтров не перемешивают список.
* При выбранном пользователе над таблицей появляется подпись «Файлы пользователя <логин>»,
  без фильтра — «Все файлы»; владелец при этом виден в каждой строке таблицы.
* Список пользователей для фильтра подгружается при первом открытии вкладки страницами
  по 100 (`GET /api/auth/users?page=N&page_size=100`), пока не набрано `count`, но не
  более 500 аккаунтов. Если аккаунтов больше, в списке будут первые 500; при
  необходимости лимит можно расширить. Если очередная страница не загрузилась, уже
  полученные пользователи остаются в списке, без модальной ошибки.

### Новости

* Создание новости (`POST /api/news`: `name`, `description`, `media_id`).
  Изображение можно загрузить кнопкой «Загрузить изображение» (`POST /api/files`, прогресс
  в `ProgressBar`) — его `id` сразу подставляется как `media_id` — или выбрать из уже
  загруженных (`GET /api/files`; фильтрация по типам-изображениям из `GET /api/files/types`
  выполняется на клиенте). Превью загружается через `ImageLoader`, `media_id` можно
  скопировать в буфер обмена, а после создания новости показывается подтверждение
  с именем, weight и `media_id`.

### Блокировка аккаунта

* Ответ `403`, `detail` которого совпадает с формулировкой бэкенда («Пользователь
  заблокирован…», «user is blocked» / «account is blocked»), клиент распознаёт как
  блокировку — сравнение точное, чтобы `403` шлюза («blocked by policy») не выкидывал
  из аккаунта. Приложение сразу забывает сессию (токен, сохранённые логин и пароль,
  файл `%LOCALAPPDATA%\CloudManagerWinUIApp\session.dat`) и показывает в главном окне
  закрываемый баннер «Вы вышли из аккаунта: <причина>». Модального диалога нет — новости
  и настройки остаются доступны без входа.
* Отказ во входе в заблокированный аккаунт `403` от `/api/auth/login` сессию не трогает:
  диалог входа остаётся открытым и показывает «Аккаунт заблокирован администратором. <detail>».
* Блокировка сохранённой сессии видна и после перезапуска: при старте приложение
  проверяет `/api/auth/me`, получает `403`, чистит сессию и снова показывает причину.
* После разблокировки сервер снова принимает прежний токен — повторный вход не обязателен.

### Ограничения админ-панели

* Признак блокировки — **текстовый** (`detail` ответа `403`) и завязан на контракт бэкенда.
  Если сервер изменит формулировку, авторазлогин перестанет срабатывать, а пользователь
  увидит обычную ошибку `403`.
* Список пользователей для фильтра файлов ограничен **500 аккаунтами** (5 страниц по 100).
  Если аккаунтов больше, в ComboBox попадут только первые 500; при необходимости лимит
  можно расширить. Ошибка загрузки отдельной страницы не очищает уже полученный список,
  но недостающие аккаунты в него не попадут.

## Известные особенности

- **Первый запуск медленнее.** Single-file сборка самораспаковывается при старте:
  ~336 файлов попадают в `%TEMP%\.net\CloudManagerWinUIApp\<hash>\`. Нужен доступ на запись в `%TEMP%`.
- **СмартСкрин.** Файл не подписан, поэтому при скачивании из интернета Windows покажет
  «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».
  Также помогает правый клик по файлу → **Свойства** → **Разблокировать**.
- **Нет идентификатора пакета (unpackaged).** Возможности из `Package.appxmanifest`
  (`systemai:Capability systemAIModels`, `runFullTrust`) в портативной сборке не действуют.
  Текущий код их не использует.

## Сборка и отладка

Всё настроено в `.vscode/`:

| Файл | Содержимое |
|---|---|
| `tasks.json` | сборка x64, публикация портативного `.exe`, запуск |
| `launch.json` | `F5` — отладка `bin\x64\Debug\...\CloudManagerWinUIApp.exe` |

**Запустить с отладчиком:** открыть проект в VS Code и нажать `F5`.

> При сборке под x64 всегда указывайте и платформу, и RID:
> `-p:Platform=x64 -p:RuntimeIdentifier=win-x64`. RID по умолчанию вычисляется
> из архитектуры текущего процесса, поэтому на ARM64-машине без явного RID
> получится рассинхрон (`0x8007000B bad image format`).
