# Владелец файла в ответах API

Документ описывает изменение контракта файлов: в ответах появились поля владельца,
чтобы клиент мог показать колонку «Пользователь» и не собирать всех пользователей
в отдельный справочник.

## 1. Новые поля

В объект файла добавлены:

| Поле | Тип | Описание |
|---|---|---|
| `creator_id` | UUID | id аккаунта, загрузившего файл |
| `creator_login` | string \| null | логин владельца; готов к показу в таблице |

Поля присутствуют во всех ручках, возвращающих файл:

* `POST /api/files` — ответ загрузки;
* `GET /api/files` — каждый элемент `data`;
* `PATCH /api/files/{file_id}` — ответ переименования;
* ответы внутренних сервисов, которые отдают тот же объект.

`creator_login` может быть `null` только если запись создана без пользователя
(служебный `ROOT_USER`). Для обычных загрузок через API он всегда заполнен.

## 2. Пример ответа

```http
GET /api/files?page=1&page_size=25
Authorization: ******
```

```json
{
  "count": 1,
  "offset": 0,
  "page": 1,
  "page_size": 25,
  "data": [
    {
      "id": "9c1f5a3e-6d2b-4b1f-9a3c-5c2d4e7f8a10",
      "name": "Договор",
      "object_key": "3f7c1d2e4b5a69788796a5b4c3d2e1f0.pdf",
      "type": "pdf",
      "size": 73400320,
      "creator_id": "0f0a5c1e-6a63-4a4d-9c2a-1e0f4b6a1c77",
      "creator_login": "desktop-user",
      "created_at": "2026-10-16T13:44:15.123456+00:00"
    }
  ]
}
```

## 3. Колонка «Пользователь»

Для таблицы достаточно `creator_login`: отдельный запрос пользователей не нужен.

```text
┌────────────────┬────────────────┬──────────┐
│ Файл           │ Пользователь   │ Размер   │
├────────────────┼────────────────┼──────────┤
│ Договор.pdf    │ desktop-user   │ 70 МБ    │
└────────────────┴────────────────┴──────────┘
```

Если логин отсутствует (`null`), покажите `creator_id` или прочерк.

## 4. Фильтр по владельцу

Фильтр `creator_id` работает как раньше и комбинируется с остальными параметрами:

```http
GET /api/files?creator_id=0f0a5c1e-6a63-4a4d-9c2a-1e0f4b6a1c77&type=pdf&page=1
```

| Параметр | Значение |
|---|---|
| `creator_id` | UUID пользователя |
| `name` | Поиск по вхождению подстроки в имя файла |
| `type` | Тип файла, параметр можно повторять |
| `page` | Номер страницы, начиная с `1` |
| `page_size` | Размер страницы, `1…100`, по умолчанию `25` |

## 5. Выбор пользователя для фильтра

Если в интерфейсе нужен выпадающий список пользователей, `GET /api/auth/users`
отдаёт их страницами (не более `100` за запрос) и поддерживает поиск по логину:

```http
GET /api/auth/users?login=desk&page=1&page_size=100
```

Рекомендации:

* подгружайте страницы последовательно по `count`/`page_size`;
* либо используйте поле `login` как поиск, а не выгружайте всех пользователей;
* в таблице файлов владельца берите из `creator_login`, чтобы не зависеть от
  загруженного списка пользователей.

## 6. Совместимость

Изменение аддитивное: существующие поля и их порядок не изменились, старые клиенты
могут игнорировать `creator_id` и `creator_login`. Миграция БД не требуется —
`creator_id` уже хранится в таблице `files`.
