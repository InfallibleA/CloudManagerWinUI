# Блокировка пользователей и фильтр файлов по пользователю

Документ описывает новый функционал API для клиента: управление блокировкой
пользователей и фильтрацию списка файлов по владельцу.

## 1. Статус блокировки пользователя

Во всех ответах, где возвращается пользователь, появилось поле `is_blocked`:

```json
{
  "id": "0f0a5c1e-6a63-4a4d-9c2a-1e0f4b6a1c77",
  "login": "desktop-user",
  "role": "client",
  "is_blocked": false,
  "created_at": "2026-10-16T13:44:15.123456+00:00"
}
```

Где встречается:

* `POST /api/auth/register` — новый пользователь создаётся с `is_blocked: false`;
* `GET /api/auth/me`;
* `GET /api/auth/users` — в каждом элементе `data`;
* ответы ручек блокировки и разблокировки.

## 2. Блокировка и разблокировка

Доступно только администратору.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/auth/users/{user_id}/block` | Заблокировать пользователя |
| `POST` | `/api/auth/users/{user_id}/unblock` | Снять блокировку |

Тело запроса не требуется. Ответ `200` — карточка пользователя с новым статусом:

```http
POST /api/auth/users/0f0a5c1e-6a63-4a4d-9c2a-1e0f4b6a1c77/block
Authorization: ******
```

```json
{
  "id": "0f0a5c1e-6a63-4a4d-9c2a-1e0f4b6a1c77",
  "login": "desktop-user",
  "role": "client",
  "is_blocked": true,
  "created_at": "2026-10-16T13:44:15.123456+00:00"
}
```

Ошибки:

| Код | `error` | Когда |
|---|---|---|
| `401` | `UnauthorizedException` | Нет заголовка `Authorization` или токен невалиден |
| `403` | `ForbiddenException` | Текущий пользователь не администратор |
| `404` | `ObjectNotFoundException` | Пользователь с таким `user_id` не найден или удалён |

Повторная блокировка уже заблокированного пользователя и повторная разблокировка
разблокированного — идемпотентны: обе возвращают `200` с актуальным статусом.

## 3. Что видит заблокированный пользователь

### Вход

`POST /api/auth/login` с правильным паролем возвращает `403`:

```json
{
  "error": "ForbiddenException",
  "detail": "Пользователь заблокирован."
}
```

Если пароль неверный, ответ прежний — `401 "Неверный логин или пароль."`:
статус блокировки не раскрывается без знания пароля.

### Ранее выданный токен

JWT не отзывается, но проверка блокировки выполняется в БД на каждом запросе.
Поэтому уже выданный токен сразу перестаёт работать: любая защищённая ручка
отвечает `403` с тем же `detail`.

Исключение — публичные ручки, которые не требуют токена (чтение новостей,
`GET /api/files/{id}/download`, `GET /api/files/{id}/image`, `/health`):
они не знают, кто вызывает, и остаются доступны.

### После разблокировки

Доступ возвращается сразу: старый токен снова работает, пока не истёк его срок.
Повторный `/login` не обязателен.

## 4. Фильтр списка файлов по пользователю

В `GET /api/files` добавлен необязательный query-параметр `creator_id` — id аккаунта
владельца файла.

```http
GET /api/files?creator_id=0f0a5c1e-6a63-4a4d-9c2a-1e0f4b6a1c77&page=1&page_size=25
Authorization: ******
```

Параметр комбинируется с существующими:

| Параметр | Значение |
|---|---|
| `creator_id` | UUID пользователя; без параметра фильтра по владельцу нет |
| `name` | Поиск по вхождению подстроки в имя файла |
| `type` | Тип файла; параметр можно повторять: `?type=png&type=jpg` |
| `page` | Номер страницы, начиная с `1` |
| `page_size` | Размер страницы, `1…100`, по умолчанию `25` |

Ответ — обычная страница:

```json
{
  "count": 1,
  "offset": 0,
  "page": 1,
  "page_size": 25,
  "data": [
    {
      "id": "9c1f5a3e-6d2b-4b1f-9a3c-5c2d4e7f8a10",
      "name": "Договор",
      "object_key": "3f7c1d2e4b5a69788796a5b4c3d2e1f0.pdf",
      "type": "pdf",
      "size": 73400320,
      "created_at": "2026-10-16T13:44:15.123456+00:00"
    }
  ]
}
```

Невалидный UUID в `creator_id` даёт `422` (стандартная ошибка FastAPI).

## 5. Рекомендуемый сценарий для админ-панели

1. Получить список пользователей: `GET /api/auth/users?login=...&role=...`.
2. Показывать в таблице колонку «Заблокирован» по полю `is_blocked`.
3. По кнопке вызывать `block` или `unblock` и обновлять строку ответом ручки.
4. Для просмотра файлов конкретного пользователя передавать его `id` в
   `GET /api/files?creator_id=<id>`.
